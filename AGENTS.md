# AGENTS.md — @artstesh-postboy-testing

Внутренние правила репозитория. Кросс-проектный процесс (связи с `artstesh-postboy` и `postboy-faq`, кросс-проектный бэклог `../backlog/cross-project.md`, синхронизация линий, релизы) описан в `../AGENTS.md` воркспейса и обязателен; здесь — только специфика этого репозитория.

## Линии и проверки

- Две живые линии: `master` (3.x, основная, peer `@artstesh/postboy ^3.4.1`) и `v1` (1.x, peer `~1.5.1`). Изменение готовится на `master` и в той же волне переносится на `v1` через `git checkout v1 && git cherry-pick -x <sha>` с адаптацией; мержить линии нельзя.
- Перед проверками на другой линии — `npm install`: линии пинуют разные версии постбоя.
- Проверки (`npm run lint && npm run typecheck && npm test`) обязаны проходить на обеих линиях. `lib/` — генерируемый вывод tsup, вручную не правится.

## Языки и файлы

- Код, TSDoc, коммиты, `AI_SKILL.md` — английский. Рабочие файлы (`docs/backlog.md`, этот файл) — русский.
- `docs/backlog.md` — внутренний бэклог; выполненный пункт помечается ✅ со ссылками на коммиты обеих линий и остаётся в списке.
- `AI_SKILL.md` есть только на `master` (пакет v1-линии его не включает) — consumer-документация ведётся на master-линии.

## Релизы и анонсы

- `npm version`/публикация — только по явной просьбе пользователя, через `../release-testing.bat` (v1 публикуется с `--tag v1-latest`).
- Работа над версией не считается законченной без черновика поста в Telegram-канал библиотеки. Посты — всегда только на английском, по голосу и шаблонам канала из `../postboy-faq/backlog/promotion/telegram.md` (релизный шаблон: один эмодзи, короткий список пользовательских изменений, ссылка `Full notes:`, 2–4 хэштега). Сообщаем об изменениях и максимум о планах — внутренних ревью, бэклогов и процессов в постах быть не должно. Текст передаётся пользователю для публикации — автоматически ничего не отправляется. Если версии выходят в обеих линиях — один пост покрывает обе.
